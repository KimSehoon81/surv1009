# 「압록강 서바이벌」 일일 작업계획 PRD

v1.0 · 2026-10-09 · 기준 문서: `docs/PRD_v0.1.md`
대상: Claude Code(Opus, 추론 노력 "높음") · Pro 요금제 · 하루 1세션 = 5시간 사용량의 약 80~90%

---

## 0. 이 문서의 역할

- 게임 PRD(`PRD_v0.1.md`)를 **45일치 작업 단위(D01~D45)** 로 나눈 실행 계획입니다.
- 매일 새 세션을 열고 `/day`(또는 아래 "일일 실행 프롬프트")만 입력하면, Claude가 `docs/PROGRESS.md`에서 다음 Day를 찾아 이 문서의 해당 절만 읽고 작업 → 검증 → 기록 → 커밋까지 진행합니다.
- **그래픽은 사용자가 별도 준비**합니다. 코드는 모든 그림을 자리표시자(색 도형 + 글자)로 먼저 그리고, `public/assets/`에 규격대로 PNG를 넣으면 자동으로 교체됩니다. 따라서 그래픽이 늦어도 작업이 막히지 않습니다. 필요 시점과 규격은 `docs/ASSETS.md`에 정리했습니다.

## 1. 하루 작업량 산정

### 1.1 기준

| 항목 | 값 |
| --- | --- |
| 하루 예산 | 5시간 창 사용량의 80~90% (Opus·높음) |
| 하루 작업 규모(목표) | 핵심 시스템 1개 또는 소형 시스템 2~3개, 신규·수정 코드 약 400~900줄 + 단위 테스트 |
| 구성 | **[필수]** ≈ 예산의 65~70% / **[여유]** ≈ 15~20% / 검증·기록·커밋 ≈ 10% |

Pro 요금제의 정확한 토큰 한도는 공개되어 있지 않고 대화 길이·파일 크기에 따라 소모량이 크게 달라집니다. 그래서 하루치를 **[필수]와 [여유]로 나눠 우선순위로 맞추는 방식**을 씁니다.

- [필수]를 먼저 끝내고, 여력이 있으면 [여유]를 진행합니다.
- 사용량이 80%에 가까워졌다고 느끼면 **"마무리해"** 라고 입력하세요. Claude는 하던 항목을 안전한 지점에서 멈추고 검증·기록·커밋만 하고 끝냅니다.
- 끝내지 못한 항목은 `PROGRESS.md`의 "이월"에 남고, 다음 날 가장 먼저 처리합니다.

### 1.2 보정(처음 3일)

D01~D03을 마친 뒤 `PROGRESS.md`의 "체감 사용량(%)" 칸에 사용자가 본 사용량을 적어 주세요. Claude가 다음 규칙으로 이후 일정을 조정합니다.

| 관찰 | 조정 |
| --- | --- |
| [필수]+[여유]를 다 끝냈는데 사용량 70% 미만 | 다음 Day의 [필수] 일부를 당겨옴 |
| [필수]만 끝내고 80~90% | 현재 분량 유지 |
| [필수]를 못 끝내고 한도 도달 | 해당 유형의 Day를 둘로 쪼개고 이후 번호를 밀어 계획 갱신 |

### 1.3 사용량 절약 규칙 (CLAUDE.md에도 동일하게 적용)

1. 세션은 하루에 새로 하나. 전날 대화를 이어가지 않음(문맥이 길수록 매 턴 비용 증가).
2. PRD 전체를 읽지 않음. 그날 Day에 적힌 **PRD 절만** 찾아 읽음.
3. 큰 파일은 필요한 부분만 읽음. 이미 아는 파일을 다시 읽지 않음.
4. 테스트·빌드 출력은 요약 모드로(`--reporter=dot`, 오류만 표시).
5. 하위 에이전트(Agent) 사용 금지. 스크린샷은 지정된 마일스톤 Day에만 1~2장.
6. 수치는 JSON 데이터로 분리해 코드 재작성 없이 조정.

### 2.1 폴더 구조 (D01에서 생성)

```
src/
  main.ts                 # Phaser 게임 설정
  config/                 # 상수(해상도, 성능 상한, 타격감 수치)
  data/                   # JSON: cards, combos, enemies, stages, skills, characters, npcs, upgrades, scaling
  core/                   # 순수 로직(Phaser 의존 금지): rng, xp, upgrades, cardJudge, deck, combos, scaling, meta, save
  scenes/                 # Boot, Preload, MainMenu, WorldMap, Prepare, Battle, Hud, Result
  systems/                # spawner, combat, feel(히트스톱·흔들림), fx, pools, spatialGrid, cards, skills, disruptions, npc, audio
  entities/               # Player, Enemy, Projectile, Pickup, Npc
  assets/manifest.ts      # 에셋 키 → 경로, 파일 없으면 자리표시자 생성
public/assets/            # 사용자가 넣는 그래픽(ASSETS.md 규격)
tests/                    # Vitest
tools/                    # 스프라이트 시트 변환 스크립트
```

### 2.2 공통 완료 기준 (모든 Day)

- `PROGRESS.md` 갱신, 커밋 메시지 `Dxx: 요약`

## 8. 일일 실행 방법

### 8.1 매일 하는 일 (사용자)

1. Claude Code에서 이 저장소로 **새 세션**을 열고, 모델 Opus·노력 "높음"을 확인합니다.
2. `/day` 를 입력합니다. (특정 Day를 지정하려면 `/day D07`)
3. 사용량이 80%대에 도달하면 `마무리해` 라고 입력합니다.
4. 세션이 끝나면 그날의 변경이 기본 브랜치(main)에 반영되었는지 확인합니다. (8.3 참고)

### 8.2 `/day`가 하는 일 (Claude)

1. `docs/PROGRESS.md`에서 다음 Day와 이월 항목 확인
2. 이 문서에서 해당 Day 절만 읽기 → 적힌 PRD 절만 읽기
3. 이월 → [필수] → [여유] 순서로 구현
4. `npm run check` 통과 확인 (실패 시 수정)
5. `PROGRESS.md` 갱신(완료·이월·메모), 커밋 `Dxx: 요약`, 푸시
6. 기본 브랜치에 병합(8.3)

`/day` 스킬이 동작하지 않는 환경이면 아래 문장을 그대로 붙여 넣어도 같습니다.

```
CLAUDE.md의 일일 작업 절차대로 오늘 작업을 진행해줘.
```

### 8.3 브랜치 운영

Claude Code 클라우드 세션은 매번 새 작업 브랜치에서 시작합니다. 다음 날 세션이 전날 작업을 보려면 전날 변경이 **기본 브랜치(main)** 에 들어가 있어야 합니다.

- 기본 운영: `/day` 마지막 단계에서 Claude가 PR을 만들고 바로 병합(squash)합니다. 1인 프로젝트 기준의 편의 설정이며, 직접 검토 후 병합하고 싶으면 `.claude/skills/day/SKILL.md`의 6단계를 지우세요.
- 세션 시작 시 Claude는 `PROGRESS.md`의 마지막 완료 Day가 현재 코드에 반영됐는지 확인하고, 반영 안 됐으면 작업 전에 알립니다.

- 규격·파일명·필요 시점: `docs/ASSETS.md`
