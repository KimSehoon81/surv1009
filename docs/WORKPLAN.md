## 0. 이 문서의 역할

- 게임 PRD를 **45일치 작업 단위(D01~D45)** 로 나눈 실행 계획입니다.
- 매일 새 세션을 열고 `docs/PROMPTS.md`의 그날 프롬프트를 붙여넣거나 `/day`를 입력하면, Claude가 이 문서의 해당 절만 읽고 작업 → 검증 → 기록 → main 반영까지 진행합니다.
- **그래픽은 사용자가 별도 준비**합니다. 코드는 모든 그림을 자리표시자(색 도형 + 글자)로 먼저 그리고, `public/assets/`에 규격대로 PNG를 넣으면 자동으로 교체됩니다. 그래픽이 늦어도 작업은 막히지 않습니다.

## 1. 하루 작업량 산정

### 1.1 기준

| 항목 | 값 |
| --- | --- |
| 하루 예산 | 5시간 창 사용량의 80~90% (Opus·높음) |
| 하루 작업 규모(목표) | 핵심 시스템 1개 또는 소형 시스템 2~3개, 신규·수정 코드 약 400~900줄 + 단위 테스트 |
| 구성 | **[필수]** ≈ 예산의 65~70% / **[여유]** ≈ 15~20% / 검증·기록·반영 ≈ 10% |

Pro 요금제의 정확한 토큰 한도는 공개되어 있지 않고, 대화 길이·파일 크기에 따라 소모량이 크게 달라집니다. 그래서 하루치를 **[필수]와 [여유]로 나눠 우선순위로 맞춥니다.**

- [필수]를 먼저 끝내고, 여력이 있으면 [여유]를 진행합니다.
- 사용량이 80%에 가까워지면 **`마무리해`** 라고 입력하세요. Claude는 하던 항목을 안전한 지점에서 멈추고 검증·기록·반영만 하고 끝냅니다.
- 끝내지 못한 항목은 `PROGRESS.md`의 "이월"에 남고, 다음 날 가장 먼저 처리합니다.

### 1.2 보정 (D01~D03 후 1회, 이후 단계 끝마다)

사용자가 `PROGRESS.md`의 "사용량" 칸에 세션 종료 시 본 사용량(%)을 적으면, D03 세션 끝에 Claude가 아래 규칙으로 이후 일정을 조정하고 "계획 변경 이력"에 남깁니다.

| 관찰 | 조정 |
| --- | --- |
| [필수]+[여유]를 다 끝냈는데 사용량 70% 미만 | 다음 Day의 [필수] 일부를 당겨옴 |
| [필수]만 끝내고 80~90% | 현재 분량 유지 |
| [필수]를 못 끝내고 한도 도달 | 비슷한 유형의 Day를 둘로 쪼개고 이후 번호를 밀어 계획 갱신 |

### 1.3 사용량 절약 규칙 (CLAUDE.md에 동일 적용)

1. 세션은 하루에 새로 하나. 전날 대화를 이어가지 않음(문맥이 길수록 매 턴 비용 증가).
2. PRD 전체를 읽지 않음. 그날 Day에 적힌 **PRD 절만** 찾아 읽음.
3. 큰 파일은 필요한 부분만. 이미 읽은 파일 재독 금지.
4. 테스트·빌드 출력은 요약 모드(오류만).
5. 하위 에이전트 사용 금지. 스크린샷은 ★마일스톤 Day에만 1~2장.
6. 수치는 JSON 데이터로 분리해 코드 재작성 없이 조정.
7. 세션 시작 시 의존성 설치·main 동기화는 SessionStart 훅이 자동 처리(대화 토큰 소모 없음).

### 2.1 폴더 구조 (D01에서 생성)

```
src/
  main.ts                 # Phaser 게임 설정
  config/                 # 상수(해상도, 성능 상한, 타격감 수치)
  data/                   # JSON: cards, combos, enemies, stages, skills, characters, npcs, upgrades, scaling
  core/                   # 순수 로직(Phaser 의존 금지): rng, xp, upgrades, combat, cardJudge, deck, combos, scaling, meta, save
  scenes/                 # Boot, Preload, MainMenu, WorldMap, Prepare, Battle, Hud, Result
  systems/                # clock, spawner, combat, feel, fx, pools, spatialGrid, cards, skills, disruptions, npc, audio
  entities/               # Player, Enemy, Projectile, Pickup, Npc
  ui/                     # 버튼·패널·목록 등 공용 위젯
  assets/manifest.ts      # 에셋 키 → 경로, 파일 없으면 자리표시자 생성
public/assets/            # 사용자가 넣는 그래픽(ASSETS.md 규격)
tests/                    # Vitest
tools/                    # 에셋 목록·검사, art/(AI 그래픽 생성·변환), 시뮬레이터
```

### 2.2 공통 완료 기준 (모든 Day)

- `npm run check` 통과 (= `tsc --noEmit` + `vitest run` + `vite build`)
- 새 규칙·수치 로직에는 단위 테스트
- `PROGRESS.md` 갱신, 커밋 메시지 `Dxx: 요약`, main 반영

## 8. 일일 실행 방법

### 8.1 매일 하는 일 (사용자)

1. Claude Code에서 이 저장소로 **새 세션**을 열고 모델 Opus, 노력 "높음" 확인
2. `docs/PROMPTS.md`에서 그날 Day 프롬프트를 복사해 붙여넣기 (또는 `/day`)
3. 사용량이 80%대가 되면 `마무리해`
4. 세션이 끝나면 `docs/PROGRESS.md`의 그날 줄 "사용량" 칸에 사용량(%)을 적기 (선택, D01~D03은 꼭)

### 8.2 Claude가 하는 일

1. (훅 자동) 의존성 설치, main 최신 커밋 동기화
2. `PROGRESS.md`에서 대상 Day·이월 확인, 이 문서의 해당 절과 지정된 PRD 절만 읽기
3. 이월 → [필수] → [여유] 순서로 구현
4. `npm run check` 통과
5. `PROGRESS.md` 진척도 갱신, 커밋 `Dxx: 요약`
6. main 반영(8.3)

### 8.3 브랜치 운영 (확정)

Claude Code 클라우드 세션은 매번 새 작업 브랜치(`claude/…`)에서 시작합니다. 다음 날 세션이 전날 작업을 이어받도록 **main을 항상 최신으로** 유지합니다.

| 순서 | 방법 | 비고 |
| --- | --- | --- |
| 1순위 | `git push origin HEAD:main` (main으로 바로 푸시) | 명령 1개, 가장 저렴. 프롬프트에 허용 문구 포함 |
| 2순위 | 세션 브랜치 푸시 → PR 생성 → squash 병합 | 1순위가 거부될 때 |
| 실패 시 | PROGRESS에 기록, 사용자에게 PR 링크 안내 | 다음 세션은 시작 시 이를 감지하고 알림 |

- 세션 시작 훅이 `origin/main`을 받아 현재 브랜치에 fast-forward로 합칩니다.
- 사용자가 직접 검토 후 병합하고 싶으면 `CLAUDE.md` 7단계를 "세션 브랜치 푸시까지"로 바꾸면 됩니다.
