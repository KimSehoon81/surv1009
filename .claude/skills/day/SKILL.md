# 일일 작업 실행

인자: 비어 있으면 PROGRESS.md의 "다음 Day". `D07`처럼 주면 그 Day.

## 절차

1. **상태 확인**: `docs/PROGRESS.md`를 읽는다. 대상 Day, 이월 항목, 결정 사항을 정리한다. 직전 완료 Day의 산출물(예: 해당 Day가 만든 파일)이 코드에 있는지 `git log --oneline -5`와 파일 존재로 확인한다. 없으면 "전날 작업이 main에 병합되지 않았습니다"라고 알리고 멈춘다.
2. **범위 읽기**: `grep -n "^### D" docs/WORKPLAN.md`로 위치를 찾아 대상 Day 절만 읽는다. 그 절의 "PRD:" 줄에 적힌 절만 `docs/PRD_v0.1.md`에서 찾아 읽는다. 사용자가 "그래픽 넣었어"라고 했으면 `docs/ASSETS.md`의 관련 부분도 읽는다.
3. **시작 보고**: 오늘 할 [필수]·[여유]·이월을 3~6줄로 보여주고 바로 진행한다(확인을 기다리지 않음).
4. **구현**: 이월 → [필수] → [여유]. 규칙 로직은 `src/core/`에 순수 함수 + Vitest 테스트. 수치는 `src/data/`.
5. **검증**: `npm run check`. 실패하면 고친다. ★마일스톤 Day면 Playwright로 스크린샷 1~2장을 `docs/screens/Dxx_*.png`로 저장한다. 그래픽을 넣은 날이면 `public/assets`의 새 파일 규격(크기·투명도·파일명)을 점검해 문제 목록을 PROGRESS 메모에 남긴다.
6. **기록**: `docs/PROGRESS.md` 일지에 한 줄 추가(날짜, 상태, 완료, 이월, 메모), "다음 Day"와 "이월 항목" 갱신, 측정값 기록.
7. **커밋·푸시**: `git add -A && git commit -m "Dxx: 요약"` 후 현재 세션 브랜치로 `git push -u origin <브랜치>`.
8. **병합**: 기본 브랜치(main)를 대상으로 PR을 만들고(제목 `Dxx: 요약`, 본문은 완료·이월 목록) squash 병합한다. 기본 브랜치가 아직 없으면 사용자에게 알리고 병합은 건너뛴다. 병합이 거부되면 PR 링크만 남긴다.
9. **종료 보고**: 완료 / 이월 / 다음 Day 를 3줄로.

## "마무리해" 를 받으면

진행 중 항목을 컴파일되는 지점에서 멈추고(미완성 기능은 설정 플래그로 비활성) 5~9단계만 수행한다. 남은 항목은 이월로 기록한다.

## 금지

- PRD·WORKPLAN 전체 읽기, 하위 에이전트 사용, 다음 Day 작업 선행(이월이 없고 [여유]까지 끝났고 사용자가 원할 때만)
- 테스트를 건너뛰거나 비활성화해서 check 통과시키기
